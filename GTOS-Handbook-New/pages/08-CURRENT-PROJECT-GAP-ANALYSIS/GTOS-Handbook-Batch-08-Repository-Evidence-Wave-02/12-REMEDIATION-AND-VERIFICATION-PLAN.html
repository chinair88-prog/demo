12 — Remediation and Verification Plan


Priority 0 — جلوگیری از False Authority #


  • PO یا declaration application status نباید legal customs release نامیده شود.
  • tenant/company/user از request به‌عنوان authority پذیرفته نشود.
  • Shipping، Warehouse، Inventory و Partner SQL کاملاً tenant-scoped شوند.
  • مالکیت Packing List، Warehouse Receipt، Shipment و Customs canonical شود.
  • tenant assignment اشتباه Shipment Item اصلاح و داده موجود migrate شود.

    • Priority 1 — Truth Preservation و Execution Safety #


  • document version/signature immutable اضافه شود.
  • outbox/inbox برای Trade Documents، Customs، Shipping، Warehouse و Inventory ایجاد شود.
  • JSON history با append-only journal جایگزین شود.
  • idempotency قبل از stock mutation بررسی شود.
  • state transition guard و optimistic version predicate اضافه شود.
  • external outcome دارای source reference، observed time، received time و correction باشد.

    • Priority 2 — تکمیل Capability #


  • Trade Quality Aggregate ساخته شود.
  • Commercial Invoice create و PL-to-CI reconciliation پیاده‌سازی شود.
  • customs document و authority-response ingestion ساخته شود.
  • CustodyRelationship با attestations پیاده شود.
  • Warehouse Receipt با typed contract به Inventory متصل شود.
  • quarantine و channel eligibility قبل از availability اعمال شود.

    • Evidence لازم برای ارتقای Status #


  • migration روی empty و upgrade database؛
  • tenant-isolation tests؛
  • concurrent posting/reservation tests؛
  • duplicate/replay tests؛
  • outbox failure/recovery؛
  • customs/provider signature verification؛
  • cross-document reconciliation؛
  • Portal E2E بدون mock fallback؛
  • audit reconstruction و backup/restore.
