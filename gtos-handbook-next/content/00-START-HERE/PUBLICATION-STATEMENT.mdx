<br />
<p>This edition consolidates the complete handbook corpus produced during the GTOS architecture program into one governed publication.</p>
<br />
<h2 id="what-this-edition-is">What this edition is</h2>
<br />
<p>- the target enterprise architecture for GTOS;</p>
<p>- the domain and lifecycle specification for global trade;</p>
<p>- the implementation guide for backend, frontend, data, events, workflows, AI, security, testing, infrastructure, and operations;</p>
<p>- the conformance baseline for engineering reviews and release readiness;</p>
<p>- the roadmap for completing and correcting the current project.</p>
<br />
<h2 id="what-this-edition-is-not">What this edition is not</h2>
<br />
<p>- a statement that the current source code already conforms;</p>
<p>- legal advice or a substitute for jurisdiction-specific counsel;</p>
<p>- proof that a deployment is secure, compliant, resilient, or production ready;</p>
<p>- permission to bypass architecture, security, financial, quality, customs, or privacy approvals.</p>
<br />
<h2 id="authority-hierarchy">Authority hierarchy</h2>
<br />
<p>1. Canon and Constitution.</p>
<p>2. Normative Core.</p>
<p>3. Detailed Volumes.</p>
<p>4. Architecture Decision Records.</p>
<p>5. Domain implementation specifications.</p>
<p>6. Code, configuration, migrations, tests, and runtime evidence.</p>
<p>7. Current-project gap reports.</p>
<br />
<p>A lower layer may implement or specialize a higher layer; it may not silently contradict it.</p>
<br />
<h2 id="final-edition-interpretation">Final-edition interpretation</h2>
<br />
<p>“Final” means the publication is a complete implementation blueprint and governed reference edition. It does not mean architecture can never evolve. Changes require an ADR, compatibility analysis, migration plan, conformance update, and release note.</p>
