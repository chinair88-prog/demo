<h2 id="test-layers">Test layers</h2>
<br />
<p>- unit tests for pure rules and invariants;</p>
<p>- property-based tests for state and numerical constraints;</p>
<p>- database/migration tests with real engines;</p>
<p>- component integration tests with real dependencies;</p>
<p>- API and Event contract tests;</p>
<p>- workflow restart, timeout, duplicate, ordering, and compensation tests;</p>
<p>- security, authorization, tenant-isolation, privacy, and abuse tests;</p>
<p>- Portal E2E tests;</p>
<p>- performance, capacity, soak, and resilience tests;</p>
<p>- backup/restore and disaster-recovery exercises;</p>
<p>- AI evaluation and adversarial tests.</p>
<br />
<h2 id="conformance-levels">Conformance levels</h2>
<br />
<p>- C0: documentation skeleton;</p>
<p>- C1: Domain semantics and contracts defined;</p>
<p>- C2: implementation and automated tests exist;</p>
<p>- C3: security, observability, recovery, and migration verified;</p>
<p>- C4: production evidence and operational ownership established;</p>
<p>- C5: independently certified for high-assurance use where required.</p>
<br />
<h2 id="release-evidence">Release evidence</h2>
<br />
<p>A release package contains versioned artifacts, SBOM, signatures, migration report, test results, security findings, compatibility report, performance evidence, runbook, rollback plan, dashboards, approvals, and known limitations.</p>
