<h2 id="verified-implementation">Verified implementation</h2>
<br />
<p><code class="code-inline">ProformaInvoiceEntity</code> maps to <code class="code-inline">tb_proforma_invoice</code>. It records PI number, supplier, customer, quotation and purchase-order references, Incoterm, currency, payment terms, prepayment ratio, ports, country, shipping method, estimated ship date, expiry date, total amount, status, notes, company, timestamps, items, and payment schedules.</p>
<br />
<p>The documented status vocabulary in source is <code class="code-inline">DRAFT</code>, <code class="code-inline">SENT</code>, <code class="code-inline">ACCEPTED</code>, <code class="code-inline">CONVERTED</code>, and <code class="code-inline">CANCELLED</code>.</p>
<br />
<p><code class="code-inline">ProformaInvoiceService</code> implements:</p>
<br />
<p>- create PI and line items;</p>
<p>- get and list;</p>
<p>- send;</p>
<p>- accept;</p>
<p>- convert to a Purchase Order reference;</p>
<p>- Events <code class="code-inline">trade.proforma-invoice.created</code>, <code class="code-inline">.sent</code>, <code class="code-inline">.accepted</code>, and <code class="code-inline">.converted</code>.</p>
<br />
<p><code class="code-inline">ProformaInvoiceController</code> exposes:</p>
<br />
<p>- <code class="code-inline">POST /api/v1/trade/proforma-invoices</code>;</p>
<p>- <code class="code-inline">GET /api/v1/trade/proforma-invoices/{id}</code>;</p>
<p>- <code class="code-inline">GET /api/v1/trade/proforma-invoices</code>;</p>
<p>- <code class="code-inline">PUT /api/v1/trade/proforma-invoices/{id}/send</code>;</p>
<p>- <code class="code-inline">PUT /api/v1/trade/proforma-invoices/{id}/accept</code>;</p>
<p>- <code class="code-inline">POST /api/v1/trade/proforma-invoices/{id}/convert</code>.</p>

<h2 id="verified-gaps">Verified gaps</h2>
<br />
<p>- Service uses a constant <code class="code-inline">DEFAULT_COMPANY_ID</code> and also assigns it as customer ID.</p>
<p>- <code class="code-inline">supplierId</code> can become null through <code class="code-inline">safeUUID</code>, while the Entity declares it non-null.</p>
<p>- No immutable PI version entity or optimistic-lock field was found.</p>
<p>- Send, accept, and convert methods do not enforce explicit source-state guards.</p>
<p>- The <code class="code-inline">purchaseOrderId</code> parameter accepted by list service is not used in the inspected query selection.</p>
<p>- PI number generation is time/random based and not a governed numbering policy.</p>
<p>- The inspected code does not establish approval, signature, beneficiary verification, expiry enforcement, or payment-risk approval.</p>
