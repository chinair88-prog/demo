<h2 id="evidence-method">Evidence Method</h2>
<br />
<p>فایل‌های Java، TypeScript و SQL پس از Repository search مستقیماً خوانده شدند. Classification فقط به کوچک‌ترین ادعای قابل دفاع اختصاص یافت.</p>
<br />
<p>تمایزهای اجباری:</p>
<br />
<p>1. Product master در برابر Marketplace catalog entry و Offer؛</p>
<p>2. calculated price در برابر published/accepted Price Version؛</p>
<p>3. cart item price در برابر authoritative checkout quote؛</p>
<p>4. Order state در برابر Inventory/Payment/Fulfilment outcome؛</p>
<p>5. shipped/delivered status در برابر carrier observation یا Proof of Delivery؛</p>
<p>6. return inspection record در برابر inventory restock execution؛</p>
<p>7. settlement calculation در برابر payout execution؛</p>
<p>8. sustainability target در برابر independently verified ESG metric؛</p>
<p>9. evaluation submission در برابر trustworthy model evaluation and governance decision.</p>
<br />
<h2 id="limitations">Limitations</h2>
<br />
<p>- Runtime configuration، migration execution و CI results مستقل اجرا نشده‌اند.</p>
<p>- وجود Test file به معنی pass بودن نیست.</p>
<p>- External payment، carrier، customer delivery، sustainability assurance و model-evaluation authority اثبات نشده‌اند.</p>
<p>- Header یا request field فقط در صورت اتصال به trusted identity context، authority محسوب می‌شود.</p>

<h2 id="critical-catalog-findings">Critical catalog findings</h2>

<h2 id="critical-findings">Critical findings</h2>
<br />
<p>1. <code class="code-inline">OrderCrudService.list()</code> در هر دو branch شرط، <code class="code-inline">repository.findAll()</code> اجرا می‌کند؛ tenant-scoped list عملاً leak دارد.</p>
<p>2. bulk approve/cancel/refund از <code class="code-inline">findAllById</code> بدون tenant filter استفاده می‌کنند.</p>
<p>3. system/internal context عمداً fail-open است.</p>
<p>4. Order Items قیمت و snapshot را از request می‌پذیرند.</p>
<p>5. <code class="code-inline">recordTransition</code> پس از تغییر status، همان status فعلی را برای from و to می‌خواند؛ local variable <code class="code-inline">from</code> استفاده نمی‌شود.</p>
<p>6. <code class="code-inline">markPaid</code> state، amount، currency، transaction uniqueness یا provider signature guard ندارد.</p>
<p>7. hold از هر status قابل اعمال است.</p>
<p>8. local Spring Event استفاده می‌شود؛ broker/outbox وجود ندارد.</p>
<p>9. <code class="code-inline">OrderWorkflowOrchestrator</code> مراحل Inventory Reservation، Payment Capture، Fulfilment، Settlement و Returns را فقط در comment ثبت کرده است.</p>
<p>10. auto-approval threshold برابر 1000 است، بدون currency normalization و risk policy.</p>

<h2 id="principal-conclusions">Principal conclusions</h2>
<br />
<p>- Product/Catalog and Pricing have multiple competing authorities.</p>
<p>- Cart and Checkout trust Client-supplied identity and price.</p>
<p>- Customer Order has a tenant leak in list and unscoped bulk workflows.</p>
<p>- Cross-service Order Saga is not implemented.</p>
<p>- Pick/Pack is executable but not connected to Inventory consumption.</p>
<p>- Last-Mile is a static in-memory optimizer and POD is absent.</p>
<p>- Returns creates useful records but auto-approves, invents actor IDs, and does not execute restock/refund.</p>
<p>- Marketplace and Payment both implement Settlement with unclear ownership.</p>
<p>- ESG Goal tracking is self-reported and duplicated across services.</p>
<p>- AI Evaluation is executable but run ownership, reviewer identity, score bounds and reproducibility are incomplete.</p>
<br />
<p>No area in this Wave is certified end-to-end complete.</p>
