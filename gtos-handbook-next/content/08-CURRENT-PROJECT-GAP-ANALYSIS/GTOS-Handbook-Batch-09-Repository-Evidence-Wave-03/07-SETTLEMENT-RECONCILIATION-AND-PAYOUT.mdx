<h2 id="competing-settlement-owners">Competing settlement owners</h2>
<br />
<p>دو Settlement Service اجرایی وجود دارد:</p>
<br />
<p>1. Marketplace Settlement:</p>
<p>   - cycles؛</p>
<p>   - transactions؛</p>
<p>   - commission/discount aggregation؛</p>
<p>   - reconciliation؛</p>
<p>   - dashboard؛</p>
<p>   - scheduler.</p>
<p>2. Payment Settlement:</p>
<p>   - batch کردن Payment Captureهای <code class="code-inline">CAPTURED</code>؛</p>
<p>   - gross/fee/net calculation؛</p>
<p>   - اتصال captureها به batch.</p>
<br />
<p>وضعیت ownership:</p>
<br />
<p><code class="code-inline">CONFLICT_REQUIRES_CANONICALIZATION</code></p>
<br />
<h2 id="marketplace-settlement">Marketplace Settlement</h2>
<br />
<p>نقاط مثبت:</p>
<br />
<p>- state transition map؛</p>
<p>- cycle calculation؛</p>
<p>- audit و metrics؛</p>
<p>- reconciliation records؛</p>
<p>- auto-generation با overlap check؛</p>
<p>- tenant-aware list endpoints.</p>
<br />
<p>Classification: <code class="code-inline">IMPLEMENTED_WITH_GAP</code>.</p>
<br />
<h3 id="material-gaps">Material gaps</h3>
<br />
<p>- tenant/company از request وارد create می‌شوند.</p>
<p>- get/update/calculate cycle by ID tenant guard آشکار ندارد.</p>
<p>- addTransaction بررسی نمی‌کند request tenant/company با cycle یکسان باشد.</p>
<p>- transaction reference authenticity و idempotency دیده نشد.</p>
<p>- Dashboard <code class="code-inline">totalCycles</code> را با global <code class="code-inline">cycleRepository.count()</code> می‌سازد و می‌تواند cross-tenant count leak کند.</p>
<p>- dashboard monetary summaries صفر hard-code شده‌اند.</p>
<p>- status <code class="code-inline">SETTLED</code> فقط state update است؛ bank/payout provider execution پیدا نشد.</p>
<p>- reconciliation actualAmount و resolvedBy از request پذیرفته می‌شوند.</p>
<p>- LLM settlement disabled است.</p>
<p>- multi-currency aggregation normalization دیده نشد.</p>
<br />
<h2 id="payment-settlement">Payment Settlement</h2>
<br />
<p>Payment service captureهای تسویه‌نشده را globally جمع می‌کند، fee rate را اعمال و Settlement Batch می‌سازد.</p>
<br />
<p>Classification: <code class="code-inline">IMPLEMENTED_WITH_GAP</code>.</p>
<br />
<h3 id="material-gaps">Material gaps</h3>
<br />
<p>- list و run settlement tenant/company scope ندارند.</p>
<p>- capture grouping بر اساس seller، tenant، currency یا payout destination نیست.</p>
<p>- تمام CAPTURED records در یک batch جمع می‌شوند.</p>
<p>- payout execution، provider transfer، retry، reconciliation و failure recovery دیده نشد.</p>
<p>- overlap با Marketplace Settlement روشن نشده است.</p>
<br />
<h2 id="canonical-boundary">Canonical boundary</h2>
<br />
<p>Payment باید money movement و provider facts را مالک باشد. Marketplace باید seller ledger، commission، entitlement و reconciliation را مالک باشد. Settlement approval نباید خودبه‌خود به معنی payout success باشد.</p>
